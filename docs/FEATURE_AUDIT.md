## 4. Recommended fixes (ordered by severity)

1. **Make the `/agent` turn non-blocking on Main.** In `app/src/main/java/com/raikaai/app/ui/chat/ChatViewModel.kt:2596-2602`, launch with `Dispatchers.IO` (or move the body of `runAgentTurn` into `withContext(Dispatchers.IO)` around `runtime.runTurn`). Without this the app can ANR for the duration of a Pi turn.
2. **Raise the Kotlin client read timeout to match the adapter.** In `app/src/main/java/com/raikaai/app/runtime/PiAgentRuntime.kt:24,174`, raise `DEFAULT_READ_TIMEOUT_MS` from `30_000` to at least the adapter's `600_000` deadline (`tools/pi-adapter/src/pi-client.js:143`), or stream `/events` incrementally instead of waiting on the prompt POST.
3. **Make tool/approval cards observable.** In `ChatViewModel.kt:279-327`, either (a) poll `/events` and emit deltas with real suspension points (`yield`/`delay`) while the turn runs, so `ToolCard`/`ApprovalCard` are rendered, or (b) remove the live-card claim from `CHANGELOG.md:17` and `README` if the panel is intentionally deferred. Also populate `ToolUiState.output` and the non-`RUNNING` `ToolStatus` values (`ToolUiState.kt:9-33`) or delete them.
4. **Fix runtime token propagation.** In `app/src/main/java/com/raikaai/app/ui/settings/SettingsScreen.kt:88-95`, drop the screen-scoped `SettingsRepository` and expose ViewModel setters for `runtimeMode`/host/port/token (mirroring `setTemperature` at `ChatViewModel.kt:4140-4143`), so a single `settingsRepo` owns `tokenBump`; alternatively make `tokenBump` an application-wide shared flow in `SettingsRepository.kt:434`.
5. **Route approval actions back to the adapter.** `respondRuntimeApproval("once"/"always")` (`ChatViewModel.kt:270-275`) only clears local state; the adapter's `approval_request` event needs an explicit allow/deny reply endpoint (today only `/v1/abort` exists — `tools/pi-adapter/src/server.js:218-220`). Add that endpoint and call it before clearing state.
6. **Select the terminal backend from `runtimeMode`, or mark the seam honestly.** In `app/src/main/java/com/raikaai/app/ui/environment/EnvironmentScreen.kt:112-117`, branch on `settings.runtimeMode` and pass `KazeTermTerminalBackend` for `KAZETERM_PI` (it already reports `isAvailable() = false`, so the existing toast path degrades safely). Otherwise reduce `TerminalBackend.kt` to one implementation and delete the unused stub.
7. **Implement the documented mode gating.** In `RaikaAIApp.kt:214-230`, hide `NavRoute.ENVIRONMENT` when `runtimeMode == ON_DEVICE`, and in `ChatViewModel.kt:2590-2604`/`SlashCommands.kt:96-130`, hide or no-op container slash commands in that mode, per `docs/PORT_PI.md:206-208`.
8. **Refresh stale docs.** `docs/ARCHITECTURE.md:20,25,51`: remove skills entries, add `runtime/`, `ToolCard`, `ApprovalCard`, `ToolCallParser` relocation, and the terminal backend seam. `README.md:50` / `README.id.md:50`: change "pause and resume" to "cancel and resume".
9. **Remove confirmed dead code.** `app/src/main/java/com/raikaai/app/ui/component/SettingsIcon.kt`, the unused `ChipsRow` import at `SettingsScreen.kt:68`, `RuntimeEvent.ThinkingDelta` (`ToolRuntime.kt:31`) if no thinking producer is planned, and the two stub-runtime tests if `ToolRuntime.call` is not wired (`DirectRuntimeTest.kt:38-44`, `ContainerRuntimeTest.kt:32-41`).

## 5. Intentional vs accidental breakage

**Intentional (do not "fix" as regressions):**

- **Legacy skills removal.** `Skill.kt`, `SkillsManager.kt`, `SkillsScreen.kt`, `SkillsSheet.kt`, `SkillImportReviewDialog.kt`, the audit test, `NavRoute.SKILLS`, proguard/ignore entries and the stale `builtin_web_researcher` gate are all gone by decision (`docs/PORT_PI.md:74-89`, `docs/KAZETERM_INTEGRATION.md:386-470`). Web search is now gated solely by `enableWebSearch` (`ChatViewModel.kt:905`). `ToolCallParser` was deliberately kept and moved to `core/tool/`.
- **KazeTerm backend stub.** `KazeTermTerminalBackend.kt:6-36` is explicitly a placeholder that fails fast and reports unavailable; the AAR is not a build dependency (`app/build.gradle.kts:152-205`). This matches `docs/PORT_PI.md:209-211` and `docs/KAZETERM_INTEGRATION.md:1.1-1.4`.
- **Pi adapter not bundled.** `tools/pi-adapter/` is a Node.js source tree with its own tests and CI (`github/workflows/pi-adapter-tests.yml`); no Pi CLI or rootfs is in the APK. `docs/PORT_PI.md:197-211` requires first-boot/on-demand install and a small `ON_DEVICE` APK.
- **Stub `ToolRuntime.call` results.** `DirectRuntime.kt:85-92` and `ContainerRuntime.kt:137-144` returning "not connected"/"unavailable" are documented seam behavior (`ToolRuntime.kt:71-78,119-123`), not a failed implementation.
- **One-round local agent path.** The 30-round loop remains remote-only by design (`docs/PORT_PI.md:35`); no regression.
- **`runtimeMode = ON_DEVICE` default.** `SettingsRepository.kt:123` and `docs/PORT_PI.md:194` agree; keeping the legacy PRoot fallback during transition is explicit (`docs/KAZETERM_INTEGRATION.md:349-358`).
